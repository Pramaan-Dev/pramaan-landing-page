# Missions: Identity & security

Verify people, stop fraud, run sign-in and check for threats.

- `site.tls.audit`: Audit a site's HTTPS security. Read a site's TLS, security headers and observed certificate facts, with ranked repairs. (steps: security.ssl.check, security.headers.check, security.certificate.lookup, security.certificate.hosts)
- `privacy.site.audit`: Audit a site's privacy signals. Read a site's cookie and data protection signals and the regulator for its stated EU or EEA country. (steps: compliance.website.gdpr, compliance.dpa.lookup)
- `bot.signup.guard`: Block bots at sign-up. Combine a challenge, email and network observations with one rate allowance into signup handling. (steps: auth.bot-check.verify, people.email.verify, security.ip.reputation, ratelimit.remaining, ratelimit.check)
- `vasp.counterparty.check`: Check a crypto service is authorised. EU crypto-service authorisation evidence and approved screening of caller-named owners. (needs approval; steps: compliance.vasp.check, identity.screening.check, compliance.aml.score)
- `domain.report`: Check a domain's risk and owner. A risk and ownership report for a domain or URL: whether it resolves and takes mail, its registration and name servers, a threat verdict for the address, and the hosting network and its abuse reputation. Findings with sources, never one risk score. (steps: security.dns.lookup, security.domain.whois, security.url.check, security.ip.lookup, security.ip.reputation)
- `file.malware.check`: Check a file for malware. Read existing file analysis and behaviour or scan a public link, retaining uncertainty. (steps: security.file.check, security.url.scan, security.file.behaviour)
- `urls.check`: Check a list of links for safety. A list of links checked at once against what security sources already hold: each is flagged, has no flags known, or was not checked. Never a statement that a link is safe. (steps: security.url.check)
- `login.risk.check`: Check a login for risk. Inspect session device, network and country-boundary facts for the builder's own allow or challenge flow. (steps: fraud.device.inspect, fraud.ip.inspect, fraud.geofence.check)
- `signup.check`: Check a sign-up for red flags. What the checks say about one sign-up, as signals that are present, absent or not checked, each with its source: the email address check, the domain's mail records and registration, and the sign-up address. No score and no verdict about the person. (steps: security.dns.lookup, people.email.verify, security.domain.whois, security.ip.lookup, security.ip.reputation)
- `face.duplicate.check`: Check a sign-up photo isn't a duplicate. Check liveness, then compare a sign-up photo only with your own enrolled faces. (needs approval; steps: identity.liveness.check, identity.face.search)
- `visitor.fraud.check`: Check a site visitor for fraud. Read existing device observations and require human review of explicit security signals. (steps: devices.visitor.get, devices.visitors.related, devices.event.get)
- `vendor.risk.check`: Check a supplier for risk. Whether a supplier is on the register, and what the domain record, DNS, URL verdict and news show about it, with a factual assessment. (steps: security.dns.lookup, security.domain.whois, companies.registry.search, companies.registry.get, security.url.check, companies.news, llm.complete)
- `site.vuln.check`: Check a website for known vulnerabilities. Known vulnerabilities in the software a website runs, from a stored technology profile of the domain (no active scanning): the technologies listed, the ones with an exact version and a registry package checked for advisories, and the ones that were not checked, each with the reason. (steps: web.tech.detect, security.vuln.lookup)
- `email.phishing.check`: Check an email for phishing. Is this message risky: each link looked up at sources that already scanned it, the From and Reply-To lines compared in code, the sender's domain record and DNS read, and the wording read for pressure tactics. Flagged, no flags known or not checked; never safe. (steps: email.message.get, security.url.check, security.domain.whois, security.dns.lookup, llm.complete)
- `breach.exposure.check`: Check if emails were in a data breach. Check known exposure for each address and return evidence with practical next steps. (steps: security.breach.check)
- `url.check.deep`: Check one URL in depth. One URL checked in depth: what security sources already hold about it, a live scan that visits the page only when asked, and the host's registration record. The answer is flagged, no flags known or not checked: never a statement that the address is safe. (steps: security.url.check, security.url.scan, security.domain.whois)
- `dependency.audit`: Check packages for known vulnerabilities. Known vulnerabilities for a typed list of exact package versions (not lockfile text): each package's advisories with severity and score, the versions with none, and the ones that were not checked, with counts. (steps: security.vuln.lookup)
- `address.proof.check`: Check proof of address. Check residential proof against supplied name and address and show separate delivery-address facts. (needs approval; steps: identity.address.verify, fraud.address.check)
- `age.gate.check`: Check someone meets a minimum age. Compare a checked document's birth date with a stated minimum age and show a separate face estimate. (needs approval; steps: identity.document.verify, identity.liveness.check, identity.age.estimate)
- `applicant.risk.review`: Check the details on a sign-up. List email, phone, IP and supplied identity match facts for a sign-up, without an overall person score or decision. (needs approval; steps: fraud.email.inspect, fraud.phone.inspect, fraud.ip.inspect, fraud.identity.check)
- `kyc.hosted.correct`: Correct a person's KYC details. Approve exact identity-data corrections on the expected person and re-read their check findings. (needs approval; steps: identity.verification.get, identity.verification.correct)
- `ip.block.decide`: Decide whether to block an IP. Suggest block, challenge or allow from separate network observations; never change a firewall. (steps: security.ip.reputation, security.ip.proxy-check, security.ip.blacklist.list, security.ip.reports.list, security.ip.block.check)
- `person.erase`: Erase a person's data everywhere. Find one person's data in the systems you connected and delete it everywhere an identifier was given, with a receipt of what was deleted. (needs approval; steps: outreach.contacts.list, auth.users.list, memory.forget, outreach.contact.delete, memory.document.delete, auth.user.delete, vector.vectors.delete)
- `kyc.erase`: Erase a person's KYC record. Erase one owned person verification and its exact fraud subject records after approval, then read status back. (needs approval; steps: identity.verification.get, identity.verification.delete, fraud.data.erase, fraud.data.erasure.get)
- `cve.brief`: Explain a security vulnerability. One vulnerability explained: the advisory record (severity, score, summary, reference links), pages that name it, and a written brief — what it is, who is affected, what to do — every sentence checked against the sources it names. No exploit steps. (steps: security.vuln.lookup, web.search, web.read, llm.complete)
- `document.wallet.fetch`: Fetch a document from a person's wallet. A person-approved document pulled from their wallet (consent link, state check, one document), then disconnected. (needs approval; steps: document.wallet.connect, document.wallet.get, document.wallet.document.get, document.wallet.national-id.get, document.wallet.disconnect)
- `national-id.fetch`: Fetch a national ID with consent. Start a consented hosted national identity session or resume it to fetch selected identity facts. (needs approval; steps: identity.national-id-session.create, identity.national-id-session.get)
- `domain.lookalikes.find`: Find lookalike domains of your brand. Domain names that are close variants of a brand's domain: fixed typo patterns and neighbouring endings looked up live, the ones with DNS records read further (registration record, threat lookup) beside the brand's own record. Facts only: a similar name says nothing about who registered it or why. (steps: security.domain.whois, security.dns.lookup, security.url.check)
- `team.invite`: Invite people to your organisation. Invite several people by email to one organisation in your auth system, skipping anyone already a member, with a receipt per person. (needs approval; steps: auth.organizations.list, auth.organization.members.list, auth.invitation.create)
- `account.lock`: Lock a user out of your app. Ban a user from signing in and end their open sessions, with a receipt of what was done. (needs approval; steps: auth.user.get, auth.user.ban, auth.sessions.list, auth.session.revoke)
- `threat.lookup`: Look up a security threat. Known threat observations for one address, domain, page or file fingerprint, with unchecked sources kept explicit. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, security.ip.reputation, security.url.check, security.ip.lookup)
- `ip.report`: Look up an IP address. Roughly where a public IP address is, who owns its network and whether it is reported for abuse: approximate location, owner, route and abuse reputation with sources. (steps: security.ip.lookup, security.ip.reputation)
- `attack.surface.report`: Map a domain's public attack surface. Observed records and technologies for one public domain, plus threat observations and caller-confirmed exact-version advisory checks. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, security.dns.lookup, web.tech.detect, security.domain.whois, security.vuln.lookup)
- `selfie.match`: Match a selfie to an ID document. Check document and selfie liveness, then compare the selfie with the same document's portrait. (needs approval; steps: identity.document.verify, identity.liveness.check, identity.face.match)
- `user.offboard`: Offboard a user from your app. Read one user, approve revocation of explicitly owned active sessions and a ban, and inspect a bounded set of memberships. (needs approval; steps: auth.user.get, auth.sessions.list, auth.organizations.list, auth.organization.members.list, auth.session.revoke, auth.user.ban)
- `video.likeness.consent`: Record consent to use someone's likeness. A verified consent record for a real person before any avatar, voice or lip-sync of them is made. (steps: media.consent.create, media.consent.attach, media.consent.get)
- `fraud.incident.file`: Report a confirmed fraud. Publish one confirmed fraud allegation about a person to the network, after showing their existing allegations, with approval on every run. (needs approval; steps: fraud.incidents.list, fraud.incident.report, fraud.incident.get)
- `host.exposure.report`: Report a server's exposed services. List observed host services, enrich known vulnerability identifiers and read matching exploit documents. (steps: security.host.lookup, security.vuln.lookup, security.exploit.search)
- `order.fraud.review`: Review an order for fraud. Gather an order's event, card, IP and location signals for a person to review in the builder's own system. (steps: fraud.transaction.assess, fraud.card.inspect, fraud.ip.inspect, fraud.geofence.check)
- `access.review`: Review who has access to your app. Who has access to your app, in which teams they sit, and who has not signed in lately, from your connected auth accounts. (steps: auth.users.list, auth.organizations.list, auth.organization.members.list, auth.sessions.list)
- `kyc.hosted.run`: Run a hosted KYC check. Start or resume a hosted identity session and read its bounded source check decisions. (needs approval; steps: identity.verification.create, identity.verification.get)
- `repo.secrets.audit`: Scan a repository for secrets. Scan supplied repository snapshot text for secret counts and return fixed rotation steps, without exposing the text or secrets. (steps: code.secrets.scan, code.repo.analyze, llm.complete)
- `privacy.site.scan`: Scan a site's cookies and trackers. The cookies and tracking services a site sets, by category, with its technologies and consent notice text. (steps: web.cookies.scan, web.tech.detect, web.read)
- `party.screen`: Screen a person or company against watchlists. Screen a person or company against lists and show candidate matches separately for human review. (needs approval; steps: identity.screening.check, identity.screening.check-advanced)
- `signup.email.screen`: Screen sign-up emails for throwaways. Inspect signup domains for disposable and free mailboxes and known mail routes, preserving each source's findings. (steps: web.domain.disposable, web.domain.email-inspect)
- `fraud.network.screen`: Screen someone against a fraud network. Consented network-screening facts ending in human review, with no automatic decision. (needs approval; steps: fraud.network-screening.create, fraud.network-screening.get, fraud.network-screening-accounts.get, fraud.incident-matches.list, fraud.incident-match.get, fraud.network-screening.review)
- `auth.enterprise-sso.setup`: Set up company single sign-on. Create and validate a company sign-in connection, prepare a challenge and inspect existing sessions; end-user sign-in remains untested. (needs approval; steps: auth.enterprise-connection.create, auth.enterprise.start, auth.sessions.list)
- `auth.backend.setup`: Set up sign-in for your app. Provision sign-in and configure origins; optionally set social credentials, create a test user and check an existing token. (needs approval; steps: auth.backend.provision, auth.backend.get, auth.backend.domains.set, auth.backend.social.set, auth.user.create, auth.token.verify)
- `kyc.verify`: Verify an identity document. Check one identity document with explicit per-check findings and a verdict computed from the requested checks. (needs approval; steps: identity.document.inspect, document.identity.extract, identity.document.forgery.check, identity.number.verify, identity.document.source.check, identity.name.compare)
- `india.identity.verify`: Verify an Indian identity document. Decode supplied identity QR facts and check the supplied national number, decoded name, PAN holder name and PAN linkage with consent. (needs approval; steps: identity.document.qr.decode, identity.number.verify, identity.identifier.lookup, identity.identifier-link.check, identity.name.compare)
