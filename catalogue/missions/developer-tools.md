# Missions: Developer tools

Code, deploys, storage, databases, workflows and documents.

- `document.ask`: Ask a question of one document. One question answered from one document: the passages are ranked against the question and the answer names the passages it rests on. (steps: document.parse, text.rerank, llm.complete)
- `warehouse.ask`: Ask questions of your data warehouse. Answer from a bounded sample of caller-selected warehouse columns, filters and order, with counts and sums worked out in code and each sentence checked against the row or facts it cites. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, llm.complete)
- `data.ask`: Ask questions of your database. A question answered from tables of your own database that you name: their rows are read, counts and sums are worked out in code, and a model answers from those rows only, naming the tables it rests on. (steps: db.tables.list, db.rows.select, llm.complete)
- `documents.ask`: Ask questions of your stored documents. A question answered from the documents stored in one of your vector indexes: the nearest passages are read, ranked against the question, and the answer names the passages it rests on. (steps: vector.index.get, text.embed, vector.vectors.query, text.rerank, llm.complete)
- `env.audit`: Audit a project's environment variables. A project's environment variable names and types, compared with a required list: which required names are missing and which present ones the list does not name. (steps: env.list)
- `incident.brief`: Brief on a live incident. Exact incident or issue facts, optional on-call rows and deployment context without guessing the cause. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, deploy.deployments.list)
- `repo.signals.brief`: Brief on a package's activity. Read package and repository activity figures, with a checked factual brief. (steps: code.npm.package, code.pypi.package, github.repo.profile, llm.complete)
- `contract.sign.cancel`: Cancel a signature request. Read a live signature request, approve cancellation and signer notification, then read back whether cancellation completed. (needs approval; steps: signature.request.get, signature.request.cancel)
- `flag.rollout.check`: Check a feature flag is ready to roll out. Checked flag configuration blockers and the evidence still needed before widening a rollout. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `launch.readiness`: Check a project is ready to go live. Whether a project is ready to go live: its domains, the email sending domain, the payment account, texting registration, app connections and social accounts, each a check with its own evidence. (steps: domains.list, security.dns.lookup, email.domain.get, payments.account.status, sms.registration.status, apps.connections.list, social.accounts.list)
- `release.health`: Check a release's health. Received events or error occurrences in checked equal windows around one deployment; missing buckets stay unknown. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, deploy.deployment.get)
- `index.health.check`: Check a search index is healthy. Read an index's configuration, sample its search, and inspect expected ids for absence, stale timestamps or wrong vector length. (steps: vector.index.get, vector.vectors.get, vector.vectors.query)
- `api.contract.check`: Check your API endpoints still respond. API endpoints called with GET and checked against the status you expect, with what changed since your last run. (steps: web.api.check, web.uptime.check, data.json.diff)
- `connections.health`: Check your connected accounts. The accounts connected to this builder — social, app connections and the payment account — one row each with what its source says about whether it still works, and counts that add up. (steps: social.accounts.list, payments.account.status, apps.connections.list)
- `csv.prepare`: Clean up a messy CSV. A messy CSV cleaned and turned into JSON rows, with the detected delimiter and the rows changed. (steps: data.csv.clean, data.csv.to-json, data.json.diff)
- `storage.cleanup`: Clean up old large files. Find old large files in one folder level, copy every enumerated version into a private archive and request approval before deleting unchanged originals. (needs approval; steps: storage.objects.list, storage.buckets.list, storage.object.versions.list, storage.object.copy, storage.object.head, storage.object.delete)
- `documents.convert.batch`: Convert up to 10 files at once. Convert up to 10 files as one job, each checked for page count and size, formats checked first. (steps: document.formats.list, document.convert-bulk)
- `preview.env.create`: Create a branch preview. Create a branch preview in an existing project and check the deployment address. (needs approval; steps: deploy.projects.list, deploy.deployment.create, deploy.deployment.get, web.read)
- `service.create.deploy`: Create and deploy a web service. Create a repository-backed web service with initial variables, start a deployment and check its reported address. (needs approval; steps: deploy.projects.list, deploy.service.create, deploy.deployment.create, deploy.deployment.get, web.read)
- `deploy.verified`: Deploy a branch as a preview. Deploy a branch as a preview (or resume on an earlier preview), read its readiness and page, and optionally promote the checked build after approval. (needs approval; steps: deploy.deployments.list, deploy.deployment.create, deploy.deployment.get, web.read, deploy.deployment.promote)
- `document.generate`: Generate a PDF from a template. Generate a PDF from unchanged caller fields and an identity-checked owned template, with app calls approved individually. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `document.classify`: Identify a document's type and language. What kind of document this is and what language it is in, from a public URL or base64 content. (steps: document.parse, text.language.detect, llm.complete)
- `documents.index`: Index your documents for search. The builder's documents parsed, split into passages and stored in one of the builder's vector indexes for search, each passage embedded to fit that index. (steps: vector.index.get, document.parse, text.embed, vector.vectors.upsert)
- `files.index`: Index your stored files for search. Files in your own storage parsed and stored for search: each file's text, chunked, embedded to fit a vector index you already have and upserted into it, with its path and text as metadata. (steps: vector.index.get, storage.objects.list, storage.object.download-url, document.parse, text.embed, vector.vectors.upsert)
- `storage.inventory`: List what's in your file storage. The buckets in your own file storage, and when asked what each holds: file, folder and byte counts of the first page of every bucket's root. (steps: storage.buckets.list, storage.objects.list)
- `contract.send.sign`: Make a contract PDF and prepare signing. Generate a contract PDF from owned template fields and prepare an approved signature draft, with optional owner-checked follow-up. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `document.watermark-copy`: Make a watermarked PDF copy. A named, watermarked PDF copy of a file for sharing. (steps: document.convert, document.watermark)
- `test.dataset.build`: Make realistic test data. Realistic made-up records in a chosen locale, checked against your schema. (steps: document.schema.validate, data.fake.generate)
- `pdf.template.manage`: Manage PDF templates. A PDF template created or updated, shown with made-up sample data before it is published. (steps: data.fake.generate, document.template.get, document.template.create, document.template.update)
- `document.layout.map`: Map a document's headings and tables. Map a document's headings, tables and pages, with the page number of each block. (steps: document.parse-layout)
- `crm.dedupe`: Merge duplicate CRM accounts. Proposed merges for duplicate live owned CRM accounts, confirmed by domain and name, with conflicts left for review. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, companies.enrich)
- `customer.onboard`: Onboard a new customer. Create a user, a billing customer and a checked welcome draft together, from one email address. Nothing is sent. (steps: auth.user.create, billing.customer.create, llm.complete, email.draft.create)
- `release.ship`: Promote a tested build to production. Stage one exact commit whose selected build passed, then approve production promotion and a checked feature flag change with a confirming read. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, deploy.projects.list, deploy.deployments.list, deploy.deployment.create, deploy.deployment.get, deploy.deployment.promote)
- `document.extract-checked`: Pull checked fields from a document. Fields from one document, every returned value checked against the text the document parsed to. (steps: document.parse, document.extract)
- `experiment.readout`: Read out an experiment's results. Checked experiment identity with the app's own conclusion, significance, probabilities and intervals as given. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `document.redact`: Redact personal details from a file. Redact text or mask Aadhaar number instances in one file, returning the reported output and explicit coverage limits. (steps: identity.document.mask, text.redact)
- `documents.remove`: Remove documents from your search index. Vector entries removed from one of your own search indexes by exact id, read first so only what is stored is removed, behind a human approval. (needs approval; steps: vector.vectors.get, vector.vectors.delete)
- `product.usage.report`: Report on product usage events. Recorded counts and week-on-week changes for caller-selected product events. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `schedules.report`: Report on scheduled jobs. Read capped schedule histories and compute spend-cap and consecutive-failure flags. (steps: schedules.list, schedule.runs.list)
- `deploy.status.report`: Report on your latest deployments. The latest deployment of each project on your own hosting account, recent deployments newest first, with failed ones called out and older failures marked superseded. (steps: deploy.projects.list, deploy.deployments.list)
- `agent.run.review`: Review a recorded AI agent run. Recorded steps, errors, durations and per-observation costs for one checked run; a trace reader, never a score against expected outputs. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `deploy.rollback.checked`: Roll back a production deploy. Read the current production deployment, select the newest caller-proven good earlier one, optionally roll back after approval, then read the target's state. (needs approval; steps: deploy.deployments.list, deploy.deployment.rollback, deploy.deployment.get)
- `secret.rotate`: Rotate a secret across deployments. Replace one secret in its checked configuration and every explicitly listed deployment use, with approvals and per-use confirmation. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, deploy.projects.list, env.list, env.set, deploy.deployment.create, deploy.deployments.list, deploy.deployment.get)
- `code.check`: Run a code snippet and check its output. Run a snippet in a supported language after approval and compare its measured output with one expected sample. (needs approval; steps: code.languages.list, code.run)
- `gpu.job.run`: Run a job on your GPU. Run one job on your own compute endpoint after approval, returning untrusted output and the reported terminal status. (needs approval; steps: gpu.endpoint.get, gpu.endpoint.health, gpu.job.submit)
- `app.action.run`: Run an action in a connected app. Find exact app actions for a caller's connection, validate caller-written arguments, and optionally execute the selected action after approval. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute)
- `service.scale.safe`: Scale a service safely. Read a service and its live deployment, check its public page and change the manual instance count within caller limits. (needs approval; steps: deploy.service.get, deploy.deployment.get, web.read, deploy.service.scale)
- `task.queue.timed`: Schedule a delayed message. Approve a delayed message with bounded delivery retries and return its cancel reference, or approve cancellation after an allowance check. (needs approval; steps: ratelimit.check, queue.message.publish, queue.message.cancel)
- `workflow.schedule.manage`: Schedule a recurring workflow. Approve creation of a capped recurring workflow run or manage an existing matching schedule, with old state and recent history. (needs approval; steps: workflow.get, schedule.get, schedule.create, schedule.pause, schedule.resume, schedule.runs.list)
- `customer.profile`: See one customer across your accounts. One customer across the builder's connected accounts: sign-in record and sessions, billing customer, subscriptions, charges, credit balances and remembered notes. (steps: auth.user.get, auth.sessions.list, billing.customers.list, billing.subscriptions.list, billing.transactions.list, billing.credits.balance, memory.profile.get)
- `document.compare`: See what changed between two documents. What changed between two versions of one document: both parsed, the differences computed in code over the two whole texts, and each one described in a checked sentence. (steps: document.parse, llm.complete)
- `trending.digest`: See what developers are talking about. What developers are talking about right now on a code host or a tech news site: the trending list, the top items read, a digest and one line per item, each checked against its own item. (steps: web.trending, web.read, llm.complete)
- `contract.template.send`: Send a contract template for signing. Read a ready contract template, verify exact signer roles and named text fields, approve sending, then read its signing status. (needs approval; steps: signature.template.get, signature.request.send-template, signature.request.get)
- `contract.sign.request`: Send documents for signing. Approve sending uploaded documents for signing, or collect an existing request: optionally remind one signer and store completed signed files and audit in a private bucket. (needs approval; steps: storage.buckets.list, signature.request.send, signature.request.get, signature.request.remind, signature.request.download, signature.request.audit, storage.object.put)
- `document.intake.route`: Send incoming files to the right reader. A file received and sent to the right reader (resume, contract, record or general), with the fields back. (steps: document.parse, llm.complete, document.resume.parse, document.contract.extract, document.records.extract, document.extract)
- `gpu.model.serve`: Serve a model on a GPU endpoint. Create a zero-minimum-worker GPU endpoint, read its health counts and approve one bounded test job. (needs approval; steps: gpu.endpoints.list, gpu.endpoint.create, gpu.endpoint.health, gpu.job.submit, gpu.job.get)
- `kv.state.share`: Share a counter or value between apps. Change one shared value, counter or list with expiry and a rate limit, returning previous values without approval. (steps: ratelimit.remaining, ratelimit.check, kv.entry.get, kv.list.range, kv.entry.expiry.get, kv.entry.set, kv.counter.add, kv.list.push, kv.entry.expiry.set)
- `gpu.cost.cleanup`: Shut down idle GPU endpoints. Find endpoints with no queued or running work and only idle workers, approve their deletion, and inventory volumes without guessing their use. (needs approval; steps: gpu.endpoints.list, gpu.volumes.list, gpu.endpoint.workers.list, gpu.endpoint.health, gpu.endpoint.delete)
- `document.summarize`: Summarise a document. A document in a paragraph and key points, from a public URL or base64 content. (steps: document.parse, llm.complete)
- `sessions.digest`: Summarise errors in recorded sessions. Measured activity and error signals from exact recorded sessions, with a checked per-session digest and limits on what they establish. (needs approval; steps: apps.connections.list, apps.catalog.search, apps.action.execute, llm.complete)
- `document.timestamp.seal`: Timestamp a document. Obtain a trusted timestamp token for a supplied SHA-256 digest, then approve signing that same digest with your connected key. (needs approval; steps: signature.timestamp.create, signature.digest.sign)
- `workflow.failures.triage`: Triage failed workflow runs. Inspect failed executions, group exact reported errors and optionally approve replay; replay is never claimed to resolve an error. (needs approval; steps: workflow.executions.search, workflow.execution.trace.get, workflow.execution.replay)
- `file.share-link`: Upload a file and get a share link. Upload a new file to a confirmed private bucket, check its metadata and return a time-limited download link. (needs approval; steps: storage.buckets.list, storage.object.put, storage.object.head, storage.object.download-url)
- `code.write.checked`: Write and test code for a task. Write source for a bounded task, check its web addresses, then run one exact-output sample after approval. (needs approval; steps: llm.complete, code.run)
- `code.release.notes`: Write release notes from commits. Write a changelog and release notes from the supplied commit-range log, withholding unsupported text. (steps: code.changelog.generate, code.release-notes.generate)
