This page describes only the security measures built today.

How we protect your data

  • Keys. An API key is shown once. Only a prefix and its last four characters are displayed after that. Keys can be revoked at once.
  • Credentials. Your own provider credentials and connection tokens are encrypted, each tied to its workspace. They are never logged or shown back.
  • Separate workspaces. Every stored record is scoped to its workspace, project and environment. Tests check that one workspace cannot read another's data.
  • Provider-neutral results. Results leave out provider names, ids and account details. Sources receive a hash of your workspace id, not your name.
  • Logs. Server logs carry request ids, key prefixes and a fingerprint of the input. They never carry request bodies or credentials.
  • Outbound calls. Web addresses that builders supply are checked, and private network addresses are blocked.
  • Inbound webhooks. Signatures are checked and repeats ignored before anything runs.
  • Sending limits. Each workspace has a daily send cap and a kill switch on Pramaan-owned SMS, email and social channels.
  • Approvals. Calls that cannot be undone, or that cost more than your limit, can require a named approver.
  • Software supply chain. Dependency versions are pinned, and new package releases are held for a day before use.
